# Frontend Overview

React 19 + Vite + TypeScript. No state management library — plain `useState`/`useMemo`/`useEffect`.

## App shell

```
#root (flex row, 100vh, overflow hidden)
  <Navbar />        ← fixed left sidebar, 240px
  <Routes />        ← flex: 1, each page handles its own scroll
```

`App.tsx` mounts `<WelcomeModal />` (fixed overlay) above the layout, then `<Navbar>` + `<Routes>`.

## Routes

| Path | Component | Purpose |
|---|---|---|
| `/` | `pages/Dashboard` | Insight overview — funnel, pain points, ICP, recommendations |
| `/chat` | `pages/Chat` | RAG chatbox with history sidebar |
| `/analysis` | `pages/Analysis` | Static "About" page explaining the system |

## Environment variables

Defined in `.env` / `.env.local`, all prefixed `VITE_`:

| Variable | Purpose |
|---|---|
| `VITE_DATA_SOURCE` | `mock` (default) or `lambda` — switches all API calls |
| `VITE_API_LAMBDA_URL` | Base URL for insights Lambda |
| `VITE_CHAT_LAMBDA_URL` | Base URL for chat Lambda |
| `VITE_INSIGHTS_BUILDER_LAMBDA_URL` | Base URL for batch Lambda |
| `VITE_API_INSIGHTS_PATH` | Path suffix for insights endpoint (default `/insights`) |
| `VITE_CHAT_PATH` | Path suffix for chat endpoint (default `/chat`) |
| `VITE_INSIGHTS_BUILDER_PATH` | Path suffix for batch endpoint |
| `VITE_AUTH_TOKEN_STORAGE_KEY` | localStorage key for auth token |

When `VITE_DATA_SOURCE=mock`, every API function returns hardcoded `MOCK_*` objects — no network calls.

## Data flow (Dashboard)

```
User selects filter (draft state) → clicks Apply
  → setPeriod / setPeriodAnchor / setMarket (applied state)
    → useEffect fires → fetchDashboardInsights({ period, date, market })
      → mock path: returns MOCK_DASHBOARD_INSIGHTS immediately
      → lambda path: GET /insights?period=&date=&market= → BeInsightResponse
        → toSummary() + toRecommendations() → SummaryData + RecommendationsData
          → setData(summary) + setRecs(recommendations)
```

## Key conventions

- All inline styles (no CSS modules, no Tailwind). Shared style objects defined as `const card`, `const inputStyle`, etc. at the top of each file.
- `recharts` v3 used for PieChart (funnel) and BarChart (pain points).
- All buttons are `<button>` with `border: none; background: none` reset from `index.css`.
- Draft/apply pattern: filter changes are buffered in `draftPeriod`/`draftAnchor`/`draftMarket` and only committed on Apply click to avoid triggering extra API calls.
- Period types: `weekly` (12 weeks), `monthly` (12 months), `quarterly` (8 quarters), `yearly` (5 years). Options generated by `getPeriodOptions(period)` going back from today.
