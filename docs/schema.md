# AI Insight Hub — Database Schema

Aurora PostgreSQL Serverless v2. Local dev: PostgreSQL via psycopg2 (seed) / pg8000 (Lambda).

---

## Tables

### `signals`

Core table. One row per signal extracted by AI from a source record.

```sql
CREATE TABLE signals (
    id               UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
    source           TEXT         NOT NULL,
    source_id        TEXT         NOT NULL,
    source_url       TEXT,
    raw_text         TEXT,
    pain_points      TEXT[],
    objections       TEXT[],
    use_cases        TEXT[],
    icp              JSONB,
    market           TEXT,
    sector           TEXT,
    funnel_stage     TEXT,
    confidence_score NUMERIC(3,2) CHECK (confidence_score BETWEEN 0 AND 1),
    embedding_text   TEXT,
    record_date      DATE,
    ingested_at      TIMESTAMPTZ,
    extracted_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);
```

| Column             | Type         | Notes |
| ------------------ | ------------ | ----- |
| `id`               | UUID         | Surrogate key |
| `source`           | TEXT         | `hubspot` · `redmine` · `twenty_crm` · `outlook_email` · `teams_transcript` · `sharepoint` |
| `source_id`        | TEXT         | Original record ID in source system |
| `source_url`       | TEXT         | Optional. Deep link to originating record. NULL for sources with no external URL (email, form). |
| `raw_text`         | TEXT         | Original unstructured text passed to LLM |
| `pain_points`      | TEXT[]       | Extracted customer pain points |
| `objections`       | TEXT[]       | Sales objections raised |
| `use_cases`        | TEXT[]       | Use cases mentioned |
| `icp`              | JSONB        | Full ICP snapshot — `company_size`, `deal_size`; used by LLM narrative and ICP cards |
| `market`           | TEXT         | Target geographic market — `vietnam` · `japan` · `korea` · `international`. Promoted from `icp.region` for indexed filtering. |
| `sector`           | TEXT         | Industry vertical — `fintech` · `logistics` · `retail` · `healthcare` · `manufacturing` · `software` · `education` · `ict` · `other`. Promoted from `icp.sector` for indexed filtering. |
| `funnel_stage`     | TEXT         | `awareness` · `consideration` · `negotiation` · `won` · `lost` |
| `confidence_score` | NUMERIC(3,2) | 0.00–1.00, model self-reported confidence |
| `embedding_text`   | TEXT         | NL summary generated by Transform; copied into `signal_embeddings` when non-empty |
| `record_date`      | DATE         | Most semantically relevant date from the source record. NULL if none. |
| `ingested_at`      | TIMESTAMPTZ  | When raw record arrived in S3 |
| `extracted_at`     | TIMESTAMPTZ  | When AI extraction completed |

#### `icp` JSONB structure

`market` and `sector` are stored both as top-level columns (for indexed query performance) and inside `icp` (for LLM context and ICP card display). The JSONB retains `company_size` and `deal_size` which are context fields, not primary filter dimensions.

```json
{
  "company_size": "50-200",
  "deal_size": "large"
}
```

| Field          | Example values |
| -------------- | -------------- |
| `company_size` | `1-10` · `11-50` · `50-200` · `200-1000` · `1000+` |
| `deal_size`    | `small` · `medium` · `large` |

```sql
ALTER TABLE signals ADD CONSTRAINT signals_funnel_stage_valid
    CHECK (funnel_stage IN ('awareness', 'consideration', 'negotiation', 'won', 'lost'));

ALTER TABLE signals ADD CONSTRAINT signals_market_valid
    CHECK (market IN ('vietnam', 'japan', 'korea', 'international'));

ALTER TABLE signals ADD CONSTRAINT signals_source_record_unique
    UNIQUE (source, source_id);
```

### `insights`

Pre-computed batch results from Feature 1 (Dashboard). Written by the batch Lambda, read by `GET /insights`.

```sql
CREATE TABLE insights (
    id           UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    computed_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    period       TEXT        NOT NULL,
    period_start DATE        NOT NULL,
    period_end   DATE        NOT NULL,
    result_type  TEXT        NOT NULL,
    market       TEXT,
    payload      JSONB       NOT NULL
);
```

| Column         | Type        | Notes |
| -------------- | ----------- | ----- |
| `period`       | TEXT        | `weekly` · `monthly` · `quarterly` · `yearly` |
| `period_start` | DATE        | First day of the compute window |
| `period_end`   | DATE        | Last day of window (`= today` when period is still open) |
| `result_type`  | TEXT        | `pain_points_summary` · `funnel_distribution` · `icp_narrative` · `recommendations` |
| `market`       | TEXT        | `vietnam` · `japan` · `korea` · `international` · NULL (NULL = aggregate across all markets) |
| `sector`       | TEXT        | Industry vertical · NULL (NULL = aggregate across all sectors) |
| `payload`      | JSONB       | LLM-generated result for this `result_type` |

Rows are **append-only** — the batch never updates existing rows, only inserts new ones. Query always selects `MAX(computed_at)` for a given `(period, period_start, market, sector)` combination.

### `signal_embeddings`

Vector store for RAG. One row per signal with a non-empty `embedding_text`.

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE signal_embeddings (
    signal_id      UUID         PRIMARY KEY REFERENCES signals(id) ON DELETE CASCADE,
    embedding_text TEXT         NOT NULL,
    embedding      vector(1024) NOT NULL,
    embedded_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    metadata       JSONB
);
```

| Column           | Type         | Notes |
| ---------------- | ------------ | ----- |
| `signal_id`      | UUID         | PK + FK → `signals.id`. 1:1. |
| `embedding_text` | TEXT         | NL summary from Transform — input to the embedder |
| `embedding`      | vector(1024) | 1024-dim vector (Bedrock prod / Gemini local) |
| `embedded_at`    | TIMESTAMPTZ  | When the vector was written |
| `metadata`       | JSONB        | Filter fields for pre-filtered similarity search: `source`, `funnel_stage`, `market`, `sector`, `source_url` |

`metadata` structure:
```json
{
  "source": "hubspot",
  "funnel_stage": "consideration",
  "market": "vietnam",
  "sector": "fintech",
  "source_url": "https://..."
}
```

### `insight_embeddings`

Vector store for RAG — semantic search over pre-computed LLM insight narratives. One row per `insights` row.

RAG chat queries **both** `signal_embeddings` (raw customer signals) and `insight_embeddings` (synthesised LLM narratives) to assemble a richer prompt context.

```sql
CREATE TABLE insight_embeddings (
    insight_id     UUID         PRIMARY KEY REFERENCES insights(id) ON DELETE CASCADE,
    embedding_text TEXT         NOT NULL,
    embedding      vector(1024) NOT NULL,
    embedded_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    metadata       JSONB
);
```

| Column           | Type         | Notes |
| ---------------- | ------------ | ----- |
| `insight_id`     | UUID         | PK + FK → `insights.id`. 1:1. |
| `embedding_text` | TEXT         | Narrative text extracted from `payload` — the text that was embedded. Derived per `result_type` (see below). |
| `embedding`      | vector(1024) | 1024-dim vector, same model as `signal_embeddings` |
| `embedded_at`    | TIMESTAMPTZ  | When the vector was written |
| `metadata`       | JSONB        | Filter fields for pre-filtered similarity search |

#### `embedding_text` derivation per `result_type`

| `result_type`          | Source fields from `payload` |
| ---------------------- | ----------------------------- |
| `pain_points_summary`  | `summary` + joined `top_items[].item + insight` |
| `funnel_distribution`  | `summary` |
| `icp_narrative`        | `narrative` + joined `top_segments` descriptions |
| `recommendations`      | `summary` + joined `sales[]` + `marketing[]` |

#### `metadata` structure

```json
{
  "period":       "monthly",
  "period_start": "2026-05-01",
  "period_end":   "2026-05-31",
  "result_type":  "pain_points_summary",
  "market":       "vietnam",
  "sector":       "fintech"
}
```

`market` and `sector` are `null` in metadata when the insight row is an aggregate (all markets / all sectors).

## Indexes

```sql
-- signals: filter and join patterns
CREATE INDEX ON signals (market);
CREATE INDEX ON signals (sector);
CREATE INDEX ON signals (market, sector);
CREATE INDEX ON signals (funnel_stage);
CREATE INDEX ON signals (source);
CREATE INDEX ON signals (extracted_at DESC);
CREATE INDEX ON signals USING GIN (pain_points);
CREATE INDEX ON signals USING GIN (icp);

-- insights: latest-per-slice lookup
CREATE INDEX ON insights (period, period_start, result_type, market);
CREATE INDEX ON insights (computed_at DESC);

-- pgvector: HNSW for ANN search + GIN for metadata pre-filter
CREATE INDEX ON signal_embeddings  USING hnsw (embedding vector_cosine_ops);
CREATE INDEX ON signal_embeddings  USING GIN  (metadata);

CREATE INDEX ON insight_embeddings USING hnsw (embedding vector_cosine_ops);
CREATE INDEX ON insight_embeddings USING GIN  (metadata);
```

## RAG query pattern (4-table join)

The chat Lambda assembles context from all four tables before calling the LLM:

```
User question
  │
  ├─ embed question → query vector
  │
  ├─ signal_embeddings  (raw signals, pre-filtered by market/sector/funnel_stage)
  │    └─ JOIN signals   (structured fields: pain_points, source_url, funnel_stage)
  │
  └─ insight_embeddings (LLM narratives, pre-filtered by period/market/sector/result_type)
       └─ JOIN insights  (period, result_type, payload)
```

This dual-source retrieval gives the LLM both granular customer evidence (signals) and synthesised trend context (insights) in a single prompt.
